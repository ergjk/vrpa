# DSH-WeChat-Agent (Vision-RPA Edition) V1.0

## 项目简介

本项目是一个基于机器人流程自动化（RPA）与视觉感知的微信智能对话代理系统。系统摒弃高风险的底层 Hook（内存注入）及非官方协议方案，采用**零注入、纯外部物理外设模拟**的技术路线。

在感知层，系统采用**「假 UIA 树（自定义视觉映射层）+ 剪贴板」双轨方案**：

- **操作界面**（切会话、点输入框、点发送）由自建的假 UIA 树通过 OpenCV 锚点图匹配完成精确定位；
- **读取消息**一味坚持**鼠标物理框选 + `Ctrl+C` 剪贴板**，不做任何图像识别。

结合大语言模型（LLM）与本地双轨持久化记忆机制，系统提供安全、稳定、具备长期记忆与拟真交互能力、支持人类在环（Human-in-the-loop）控制的自动化解决方案。

> 项目状态：**设计完成，等待主控官确认施工清单后按 M0~M6 逐项实现**。
> 当前仓库仅包含文档，尚无代码文件。

## 核心特性

### 1. 零 Hook 风控规避 + 假 UIA 树视觉映射
系统全程模拟真实用户的物理外设操作（鼠标坐标点击、区域拖拽、剪贴板读写、回车），不触碰微信客户端底层内存与通信协议。
微信 4.x 不再暴露可用的原生 UIA 控件树，因此系统自建**假 UIA 树**：用本地 JSON 描述界面元素树（相对比例坐标 0~1 + 特征截图 Anchor Image），执行动作前用 OpenCV 做多尺度模板匹配定位。**匹配不到即中止重试，绝不猜坐标**。细节见 [感知层规范](#感知层规范假-uia-树自定义视觉映射层)。

### 2. 双库分离记忆架构 (Dual-Memory Architecture)
本地严格数据解耦，两个独立存储模块：
- **流水记忆库 (Chat History Database)**：存储屏幕实时抓取的短期上下文，用于维持当前话题连贯性、防上下文超限。
- **核心档案库 (Long-Term Memory Database)**：存储由模型异步提炼的核心事实（用户画像、偏好、重要事件等），结构化持久化。

### 3. 状态回写与自指识别 (State Write-back & Self-Awareness)
针对微信界面不显示自身昵称及多端并发（如手机端发送）的痛点，系统引入状态回写机制：发送成功后立即把输出内容以 `assistant` 角色写入流水库；下一轮抓屏通过文本哈希比对去重。非本程序发出且无前缀的消息，识别为「主人在其他设备发送」，仅入库不回复，杜绝逻辑死循环。

### 4. 拟人化随机延迟与队列调度 (Human-like Delay & Queue Scheduling)
为应对多对象并发监听及规避「秒回」风控，引入 FIFO 消息队列与拟人化延迟：环境感知、逻辑思考、文本输入、发送各环节均加入符合人类行为特征的随机延迟（2~8 秒级，可配置），并支持静默时段与限流。既缓冲 RPA 界面状态突变风险，也提升拟真度。

### 5. 人类在环控制通道 (Human-in-the-loop Control Plane)
独立于微信数据流的旁路控制台：主控官可通过终端下达指令，动态修改执行人格、查询/总结双库记忆、暂停/恢复、或直接接管发送指定文本，实现可控的监督式自动化。

### 6. 可插拔式扩展架构 (Pluggable Extension Architecture)
核心逻辑极简，非高频扩展（如朋友圈发布）设计为可插拔独立模块，默认关闭，启用后由主控台指令触发 RPA 自动发布。配套标准元数据结构供二次开发。

## 系统架构

六层解耦架构，各模块高内聚、低耦合：

### 1. 感知层 (Perception Layer)
- **组件**：`pywinauto`（仅顶层窗口/客户端矩形）、自建假 UIA 树（`uia_tree` + `anchor_match` + OpenCV）、`pyautogui`（鼠标）、`pyperclip`（剪贴板）、`parser`
- **职责**：
  - 用假 UIA 树定位界面元素（切会话、点击输入框/发送、检测弹窗遮挡）；
  - 在消息区执行物理框选并触发 `Ctrl+C`，读取剪贴板纯文本；
  - 将剪贴板文本解析为结构化消息（发送者、时间戳、内容）。
- **边界**：**图像识别只服务「操作界面」，绝不用于读取/判断消息内容**（红线，见下）。

### 2. 记忆层 (Memory Layer)
- **组件**：SQLite 双库（流水库 + 档案库，WAL 模式）、去重对齐引擎（尾部锚点）、DSH 记忆模块
- **职责**：历史流水截断与比对、自我消息去重、多端消息判定；长期记忆检索；解析控制指令并路由。

### 3. 推理层 (Inference Layer)
- **组件**：DeepSeek API / OpenAI 兼容端点
- **职责**：接收记忆层组装的上下文与 Persona，进行语义理解与回复生成；输出清洗、长度/敏感词/链接安全过滤。

### 4. 执行层 (Execution Layer)
- **组件**：`pyautogui` + `pyperclip` + 假 UIA 树定位
- **职责**：定位输入框 → 粘贴 → `Ctrl+A/Ctrl+C` 回读校验 → 回车发送 → 状态回写；发送前做「会话 / 焦点 / 内容」三重校验。

### 5. 控制层 (Control Layer)
- **组件**：独立 CLI 终端（线程安全）
- **职责**：暂停/恢复、人设热更新、记忆检索与总结、直接接管发送、重跑校准、插件管理。

### 6. 扩展接口层 (Extension API Layer)
- **组件**：RPA Action Engine、Task Scheduler、`Moments_Log` (Optional)、插件协议
- **职责**：`#发圈` 等高级指令；保留数据库结构供扩展二次开发；插件只能通过受限 `AgentContext` 调用能力，不得直接操作鼠标键盘。

## 感知层规范：假 UIA 树（自定义视觉映射层）

> 本节为 V1.0 的**强制性感知层规范**，实现不得偏离。完整设计见 [技术方案-V1.0.md](docs/技术方案-V1.0.md) §4.3 / §6.2。

### 1. 定义
在本地通过 JSON 文件定义一棵**结构化的界面元素映射树**（"假 UIA 树"），描述微信窗口内所有需要操作的元素。它替代微信 4.x 缺失的原生控件树，只用于**操作界面**，不用于读取消息。

### 2. 元素结构
每个元素记录：
- **相对比例坐标（0~1）**：相对父元素（根节点相对窗口客户区），兼容窗口移动/缩放；
- **特征截图（Anchor Image）**：该区域截图，可多张（多状态/深色模式备选），按序尝试；
- **元信息**：`id`、`role`（容器 / 区域 / 锚点）、`purpose`（点击 / 输入 / 拖拽 / 守卫 / 插件）、`required`、匹配阈值（可逐元素覆盖）。

V1.0 必需元素：`main_window`、`message_area`（仅提供框选拖拽坐标）、`search_box`、`input_box`；可选：`send_button`、`popup_close`、`moments_entry`（插件用）。

### 3. 定位原理
1. 取微信顶层窗口的**客户端矩形**（`pywinauto`，只用这一处窗口 API）；
2. 沿元素树 parent 链找到最近已定位祖先，裁剪对应屏幕区域；
3. 用 **OpenCV 多尺度模板匹配**（`TM_CCOEFF_NORMED`、灰度、缩放 0.9~1.1、大区域降采样）在该区域匹配 Anchor Image；
4. **匹配成功**：按「匹配偏移 + 相对比例」换算绝对坐标，点击/输入；
5. **匹配失败（分数低于阈值）**：视为 `ElementNotVisible`，**立即中止本次操作并重试**（抖动等待 2 次），仍失败则截图留证、跳过本会话；**绝不复用上次坐标、绝不用比例坐标兜底硬点**；
6. 分辨率/DPI 与 profile 不符、或窗口矩形偏差 > 2%：`ProfileMismatch`，拒绝动作并提示重跑 `/calibrate`。

### 4. 边界（硬红线）
- 假 UIA 树**仅用于"操作界面（点击、输入）"**；
- **消息流（聊天记录）的采集依然死死咬住「鼠标物理框选 + Ctrl+C 剪贴板」方案，绝对不允许在消息流上做图像识别/OCR**；
- 编码层强制执行：`perception/capture.py`、`perception/parser.py`、`memory/dedup.py` 禁止 import `cv2` / `anchor_match` / `vision`，由 `tests/test_boundary.py` 静态断言；`capture()` 返回的字符串是消息内容的唯一入口。

### 5. 校准与校验
- `wechat_agent calibrate`：逐元素框选 → 保存锚点图 + 比例 → 立即自匹配回验（≥0.98）→ 输出 JSON 与 overlay 截图供人工确认；
- `wechat_agent validate-tree --strict`：对所有必需锚点元素做现场自检，任一失败即非 0 退出（启动前/换分辨率后必跑）；
- profile 按「分辨率@DPI」分文件（如 `2560x1440@1.25`），深浅色主题可各录一套锚点图。

## 工作机理与数据流生命周期

系统基于「事件驱动」与「状态机」，核心闭环：

1. **触发与定位**：定时器触发；假 UIA 树定位 `search_box` 切到目标会话，定位 `message_area` 作为框选区域。
2. **采集**：在消息区模拟鼠标拖拽框选 → `Ctrl+C` → 读剪贴板（唯一消息来源）。
3. **清洗与并发路由**：解析为结构化消息；流水库比对：
   - 已在库中 → 历史记录，忽略；
   - 无前缀且不在库中 → 多端并发（主人手机发送），标记 `self` 入库，结束流程；
   - 有前缀（他人发送）→ 推入 FIFO 队列（同会话连发合并为一批）。
4. **上下文构建**：检索核心档案库长期记忆 + 会话摘要 + 最近 N 轮流水，注入当前人格 Prompt。
5. **推理与延迟**：调用 LLM 生成响应，并施加拟人化随机延迟（拟思考、拟打字节奏）。
6. **执行与前置校验**：假 UIA 树定位输入框 → 粘贴 → 回读比对 → 会话/焦点/内容三重校验 → 回车发送；必要时点击 `send_button`。
7. **状态回写**：发送成功后立即以 `assistant` 角色写入流水库，闭合去重状态；失败则截图留证、计数、必要时自动暂停。

## 运行环境与依赖

### 物理环境要求
- **操作系统**：Windows 10 / Windows 11。
- **显示环境**：建议独立物理显示器（副屏）或虚拟机隔离运行，保证微信窗口常驻前台、避免被真实用户干扰。
- **客户端配置**：微信 PC **4.x**（目标版本，假 UIA 树按该版本校准）；无需降级、不装任何补丁。
- **权限**：普通用户权限即可；不要求管理员、不装驱动、不注入进程。

### 核心依赖
- **基础运行环境**：`Python 3.10+`
- **自动化控制**：`pyautogui`（键鼠模拟）、`pywinauto`（顶层窗口句柄）、`pyperclip`（剪贴板）
- **视觉定位**：`opencv-python`、`numpy`、`Pillow`（假 UIA 树锚点图匹配、截图留证）
- **AI 接口**：`openai` SDK（兼容 DeepSeek API）
- **本地存储**：`sqlite3`（内置，WAL）
- **配置/界面/热键**：`PyYAML`、`rich`(可选)、`pynput`(急停热键)
- **测试**：`pytest`

> V1.0 不引入 PaddleOCR 等重型视觉/多模态依赖。

### 红线 3：感知层消息流边界
- 假 UIA 树只用于操作界面；**消息流只准走「鼠标物理框选 + `Ctrl+C` 剪贴板」**。

## 局限性与安全声明

1. **独占限制**：基于系统级 RPA 特性，程序运行期间会抢占鼠标控制权。建议结合副屏方案与拟人化延迟，避免物理操作冲突；提供全局急停热键与暂停指令。
2. **分辨率/主题依赖**：假 UIA 树依赖固定窗口布局与锚点图；窗口大小、系统缩放、微信主题（深色/浅色）变化后需重新执行锚点校准。校准失效时系统**中止动作而非猜测**（可能表现为"暂时不回复"）。
3. **富文本局限**：无法直接解析图片、语音、视频或复杂富文本，仅处理纯文本消息。
4. **环境突变**：微信客户端重大版本更新可能导致 UI 元素无法被匹配，需重录锚点图或升级底层驱动库。
5. **账号风险**：系统采用零注入 + 低频拟人化策略降低风险，但任何第三方自动化都存在平台规则风险，请自行评估、仅用于个人合规场景，勿用于营销群发、自动加好友等行为。

## 附录 A：Roadmap（V1.1 / V1.2，仅规划，V1.0 不实现）

> 以下功能在 V1.0 阶段**仅保留空接口定义**，任何具体实现代码均属越界，需主控官立项后再开发。

### V1.1（拟真交互扩展）
1. **动画表情支持**：本地 `emoji_lib` 表情截图库 + 人工情绪标签，图像匹配点击发送。难度：极高（受 RPA 视觉盲区限制）。
2. **语音/TTS 发声**：TTS 生成音频 + 虚拟声卡 + RPA 模拟长按；或降级为发送音频文件。难度：高。
3. **消息撤回与情绪模拟（Self-Reflection）**：发送后延迟二次审查，判定"后悔"则右键撤回并让模型补救。难度：极高（2 分钟时限 + 右键菜单精准定位）。
4. **开放式插件生态**：`#红包`、`#拍一拍` 等社区插件。

### V1.2（行为克隆与多模态，方向性规划）
- 行为克隆（学习主人的回复节奏/口癖/常用语）、生图等多模态扩展。**V1.0 不立项、不写代码。**

```powershell
# 1. 安装依赖（待 requirements.txt 落地）
pip install -r requirements.txt

# 2. 配置
copy .env.example .env      # 填入 DEEPSEEK_API_KEY
# 编辑 config.yaml：目标会话、限流、拟人延迟
```
