# VRPA-WeChat-Agent（Vision-RPA Edition）V1.0 详细技术方案

> 文档性质：实现前的技术设计（不包含完整代码，包含接口约定、数据结构、关键算法伪代码）。
> 依据：仓库根目录 `README.md`（V1.0 六层架构、假 UIA 树感知层规范）。
> 施工图：[行动清单-V1.0.md](行动清单-V1.0.md)（M0~M6 任务 / 输入输出 / DoD）。
> 目标：让 1～2 名工程师可以照着本文档直接开工，且关键风险点在编码前被显式确认。

## 1. 目标、范围与验收口径

### 1.1 V1.0 必须做到（In Scope）

| 编号 | 能力 | 验收口径 |
|---|---|---|
| F1 | 窗口发现与前台激活 | 能按标题/进程名找到微信主窗，激活并取得客户端矩形 |
| F1b | 界面元素定位（假 UIA 树） | JSON 元素树 + 锚点图多尺度匹配 → 返回绝对坐标；未达阈值立即中止并重试，绝不猜坐标 |
| F2 | 消息采集 | 在指定会话中框选消息区 → Ctrl+C → 剪贴板 → 解析为结构化消息列表（含发送者、时间戳、内容） |
| F3 | 增量去重 | 重复抓取不产生重复入库；自己发出的消息不触发二次回复 |
| F4 | 多端识别 | 无前缀且不在库中的消息判为「主人手机端发送」，入库不回复 |
| F5 | 对话生成 | 组装 Persona + 长期记忆 + 最近 N 轮，调用 DeepSeek（OpenAI 兼容）生成回复 |
| F6 | 拟人延迟 | 全链路随机延迟（感知/思考/输入/发送），可配置区间与限流 |
| F7 | 发送与校验 | 粘贴后二次校验窗口/焦点/内容，再回车；发送后状态回写 |
| F8 | 双库记忆 | 流水库（chat_history）+ 核心档案库（memory）物理分离，长期记忆可从流水异步提炼 |
| F9 | 控制台 | 暂停/恢复、人设热更新、记忆查询与总结、直接接管发送、状态查看、锚点重校准 |
| F10 | 异常自保 | 连续失败自动暂停 + 截图留证 + 全局急停热键 |
| F11 | 可插拔扩展 | 插件基类 + `#发圈` 示例插件（默认关闭） |

### 1.2 明确不做（Out of Scope，V1.1/V1.2 预留）

- 动画表情 / 语音 / TTS / 图片与富文本理解（仅纯文本）。
- 消息撤回与情绪二次审查（仅保留 `self_review` 钩子位，不实现 RPA 右键菜单）。
- 生图与多模态扩展、行为克隆（V1.2）。
- 多微信实例、多账号、手机端协议、Hook/注入（永久排除）。
- **超前开发红线**：V1.0 阶段上述能力**不得出现任何具体实现代码**，只允许在 `core/interfaces.py` 保留空 Protocol 定义（不实现、不接线、不写测试）。

### 1.3 非功能指标

- 单轮「发现新消息 → 发送完成」端到端延迟 4～12 秒（可配）。
- 单会话连续运行 8 小时无坐标漂移失控；崩溃重启后不重复回复、不丢已发记录。
- 任何一次发送都可审计（谁触发、上下文、原文、结果）。
- 无网络时降级：停止发送并保持采集，本地队列不丢。

## 2. 技术路线与关键取舍

| 决策点 | 选择 | 理由 / 被否方案 |
|---|---|---|
| 微信接入方式 | 纯外部 RPA（pywinauto 找窗 + pyautogui 鼠标键盘 + pyperclip 剪贴板） | README 明确零 Hook；封号风险主要来自协议/注入 |
| 消息读取 | **框选 + Ctrl+C 取纯文本**（硬红线：消息内容禁止任何图像识别/OCR） | 剪贴板是唯一稳定、无依赖的「结构化」来源；OCR 体积大、中文误识率高，图像识别消息流会引入不可接受的误读 |
| 界面元素定位 | **假 UIA 树（自定义视觉映射层）**：JSON 元素树 + 相对比例坐标 + 特征截图（Anchor Image）多尺度模板匹配 → 换绝对坐标；匹配失败立即中止重试，**禁止坐标兜底猜测** | 微信 4.x 无原生 UIA 控件树，纯比例坐标在弹窗/界面突变时会点错；图像匹配只回答「点哪里」，不碰消息内容 |
| 输入方式 | **仅剪贴板粘贴**，禁止 `typewrite` 输入中文 | pyautogui 无法输入 Unicode 中文；输入法状态也会干扰 |
| 存储 | SQLite（WAL）双库 + FTS5 | 轻量、事务可靠、零服务；JSON 无法支撑去重查询与并发读写 |
| 记忆检索 | V1 用「关键词/近期 + 重要度」召回；预留 embedding 列 | 避免一次性引入向量库；schema 预留 `embedding BLOB` 便于升级 |
| 并发模型 | 单 RPA 执行线程 + 队列 + 多会话轮转调度；采集/推理/控制台各自线程，共享 `rpa_lock` | RPA 独占鼠标键盘，物理上不可能真并发 |
| 推理接口 | OpenAI SDK 兼容层（DeepSeek `deepseek-chat`），可换 base_url | README 指定 |

### 2.1 硬约束（必须在代码里体现）

1. 任何鼠标/键盘动作前必须持有 `rpa_lock`；控制台「接管发送」需要打断等待中的延迟。
2. 所有延迟用 `Event.wait(delay)` 而非 `time.sleep`，保证急停/接管可秒级响应。
3. 感知层与执行层必须抽象成接口（`Protocol`/`ABC`），使测试可注入 `FakePerception`/`FakeExecutor`，**不依赖真机即可跑通全流程**。
4. 发送动作必须幂等：同一 `dedup_key` 的重试不得发出第二条。
5. 所有界面动作（切会话/点击输入框/粘贴/发送）必须先经假 UIA 树 `locate(element)` 取得绝对坐标；`locate` 失败 = `ElementNotVisible`，一律中止，**不得复用上一次坐标、不得用比例坐标强点**。
6. 消息流路径（`perception/capture.py`、`perception/parser.py`、`memory/dedup.py`）**禁止 import cv2 或 anchor_match**，由 `tests/test_boundary.py` 静态断言强制。
7. 假 UIA 树只回答「点哪里/输到哪」，**不回答「说了什么」**；消息内容只能来自剪贴板。

## 4. 配置设计

### 4.1 `config.yaml`（示例）

> M0-F-03 已把配置升级为 **schema v2**：平台字段移入 `platform: {kind, options}`，旧 schema v1（顶层 `wechat:` 段）会自动升级并打印迁移提示；环境变量统一 `VRPA_*`。以下示例保留 schema v1 结构仅作历史参照，实际以仓库根 `config.yaml` 为准。

```yaml
app:
  log_level: INFO
  data_dir: ./data
  dry_run: false                 # true = 只采集/推理，不真实发送（强烈建议首次运行开启）
  tick_interval: 2.0             # 主循环轮询间隔（秒）
  max_hours: 8                   # 连续运行上限，超时自动暂停

wechat:
  window_title_regex: "^(微信|WeChat)$"
  process_names: ["WeChat.exe", "WeChatAppEx.exe"]
  activate_before_action: true
  chat_type_default: private       # private | group（按会话单独配置见 chats 表）
  switch_chat: search_box          # search_box（推荐） | session_list

# —— 假 UIA 树（自定义视觉映射层，V1.0 感知层核心）——
uia_tree:
  profile: auto                    # auto = "<分辨率>@<DPI>"，如 "2560x1440@1.25"
  dir: ./data/uia_tree
  anchors_dir: ./data/anchors
  cache_ttl: 2.0                   # 定位结果缓存（秒）；任何点击/滚动/发送后立即整体失效
  match:
    threshold: 0.88                # 低于此分视为「找不到」
    scales: [0.9, 0.95, 1.0, 1.05, 1.1]
    grayscale: true
    max_side_px: 1600              # 匹配前降采样上限，单次 locate 目标 < 60ms
  locate_retries: 2                # 找不到 → 立即中止本 tick 并重试
  retry_wait: [0.4, 1.2]
  allow_ratio_fallback: false      # 硬性 false：可点击元素必须有锚点图

# —— 消息流采集（硬红线：只有这条路径可以读消息内容）——
capture:
  drag:
    from: {x: 0.94, y: 0.14}       # 相对 message_area 元素的比例（避开滚动条/头像）
    to:   {x: 0.06, y: 0.92}
    steps: 18                      # 分段移动步数（模拟人手，避免整块选中 UI）
    duration: 0.45                 # 拖拽总时长（秒）
  copy_wait: 0.35                  # Ctrl+C 后等待剪贴板稳定的时间
  min_messages: 3                  # 一屏少于 3 条视为异常（滚动/遮罩）
  lookback_screens: 3              # 首次/失锚时向上回滚屏数
  dedup_recent_window: 200         # 去重时参考的库内最近条数
  low_confidence_policy: ignore    # ignore | queue_confirm
  title_verify: capture_first_sender   # 会话校验方式（用采集到的首条发送者比对会话名）

llm:
  provider: deepseek
  base_url: https://api.deepseek.com
  model: deepseek-chat
  temperature: 1.15
  max_tokens: 400
  timeout: 25
  retries: 3
  history_turns: 12                # 注入的最近对话轮数上限
  max_prompt_tokens: 3000
  memory_top_k: 6
  fail_policy: hold                # hold（转人工）| skip

humanize:
  perception_delay: [0.3, 1.2]
  think_delay: [1.5, 5.0]          # 思考
  typing_ms_per_char: [35, 90]     # 打字节奏
  pre_send_delay: [0.3, 1.4]
  long_reply_extra: [1.0, 3.0]     # 长文本额外停顿
  jitter_enabled: true

ratelimit:
  per_chat_per_minute: 6
  per_chat_per_day: 300
  global_per_hour: 120
  quiet_hours: ["01:00-07:30"]     # 静默时段只入库不回复
  cooldown_after_send: [2, 5]

safety:
  panic_hotkey: "ctrl+alt+q"
  pause_hotkey: "ctrl+alt+p"
  max_consecutive_failures: 3
  screenshot_on_failure: true
  sensitive_words: ["身份证", "密码", "转账"]
  max_reply_chars: 300
  block_links: true

control:
  nlu_enabled: true                # 允许自然语言指令（需 LLM）
  confirm_override_send: true      # /say 前二次确认

plugins:
  moments:
    enabled: false
    default_visibility: private
```

规则（`perception/uia_tree.py` 加载时强制校验）：

- `roi` 相对 **parent 元素的绝对矩形**；根节点矩形来自 pywinauto 顶层窗口客户端区（只取窗口句柄/矩形，不用内部控件树）。
- `role` 三态：`container`（仅比例，不匹配）/ `region`（仅比例，用于拖拽、滚动等区域操作）/ `anchor`（必须带非空 `anchor_images`，可点击/可校验）。
- **可点击元素必须是 `anchor` 且有锚点图**；缺失 → `TreeConfigError`（对应 `allow_ratio_fallback: false`，不存在"用比例硬点"的降级）。
- `anchor_images` 是**有序数组**：按序尝试匹配，命中即用。同一元素多状态（如输入框聚焦/未聚焦）或深色/浅色主题可各录一张；校准向导默认录一张，`/calibrate --add-anchor <id>` 追加。数组中所有文件必须存在。
- 锚点图放 `data/anchors/<profile>/<文件名>`，PNG，尺寸≈该元素 ROI 截图（含少量内边距，由校准向导自动裁剪）。
- `match` 可逐元素覆盖全局参数；`threshold` 建议 0.88~0.92（过低误命中、过高误拒）。
- `purpose`：`click` / `input` / `drag` / `guard` / `plugin`（V1.0 只有 `moments` 预留 plugin 元素）。
- 每个 profile 绑定「分辨率 + DPI」；运行时 `display` 与实际不符或 `client_rect` 与校准偏差 > 2% → `ProfileMismatch`，**拒绝启动/中止动作并提示重跑校准**（不猜坐标）。
- `validation.self_check` 是校准结束时的自匹配分数，`validate-tree` 用它与现场重测对比，偏差 > 0.05 即提示「界面可能已变化」。

## 6. 感知层：假 UIA 树定位 + 剪贴板采集 + 去重（核心难点）

### 6.0 边界红线（违反即返工）

| 允许 | 禁止 |
|---|---|
| 假 UIA 树 + 锚点图匹配，用于**操作界面**：切会话、点输入框、点发送、检测弹窗、提供框选拖拽区域 | 用图像识别/模板匹配/OCR **读取或判断消息内容** |
| 鼠标框选 + `Ctrl+C` + 剪贴板读取消息（唯一消息来源） | 用假树匹配结果/像素差推断对方说了什么 |
| `vision.py` 做截图留证、可视化 overlay、失败诊断 | `vision.py` 或 `anchor_match` 出现在消息解析/去重调用链上 |

强制手段：`tests/test_boundary.py` 静态断言 `perception/capture.py`、`perception/parser.py`、`memory/dedup.py` 的 import 集合不得包含 `cv2` / `anchor_match`（或 `vision`），且消息数据的唯一入口是 `capture()` 返回的字符串。

### 6.1 顶层窗口定位与激活（pywinauto，仅顶层）

```python
# perception/window.py（伪代码）
def find_main_window(cfg) -> Window:

```

- 微信 4.x 无原生内部控件树，**因此只取「进程名 + 标题 + 客户端矩形」三样**，其余界面几何全部交给假 UIA 树（§6.2）。
- 标题只用于「确认前台是微信」，**不用于识别当前会话**（会话校验见 §6.3.1，走剪贴板路径）。
- 客户端矩形每次动作前重新获取（窗口可能被移动/缩放）；`client_rect` 与 profile 校准值偏差 > 2% → `ProfileMismatch`，中止并提示 `/calibrate`。
- 激活失败 → 重试 2 次 → `WindowNotFound`/`WindowNotForeground`；`max_consecutive_failures` 次后自动 `PAUSED`。

### 6.2 假 UIA 树（自定义视觉映射层）定位算法

#### 6.2.1 加载与校验
- 加载 `data/uia_tree/<profile>.json`（结构见 §4.3），校验：schema 版本、`display` 与实际分辨率/DPI 一致、每个 `anchor` 元素锚点图存在且尺寸 > 8×8、可点击元素不得缺图、父子引用无环。
- 加载成功构建内存树 `TreeIndex{element_id -> ElementNode(parent, roi, image_path, match, purpose, required)}`。
- `validate-tree --strict`：对每个 required `anchor` 元素做一次真实自匹配，输出 `id / 期望阈值 / 实测分数 / 绝对 rect`；任一 required 元素低于阈值或找不到 → 非 0 退出。

#### 6.2.2 `locate(element_id) -> Rect` 流程

```python
def locate(element_id: str, *, force_refresh=False) -> Rect:
    if not force_refresh and cache.hit(element_id):
        return cache.get(element_id)
    node = tree[element_id]
    ancestor = nearest_located_ancestor(node)  # 沿 parent 链；缓存有效则直接复用
    base = ancestor.abs_rect if ancestor else client_rect(wechat_window)
    region = crop_screen(base)  # PIL.ImageGrab，支持多屏/负坐标
    if node.role == "anchor":
        score, offset, scale = match_template(region, load_anchor(node), node.match)
        if score < node.match.threshold:  # 找不到 → 立即中止（不猜坐标）
            raise ElementNotVisible(node.id, score, expect=node.match.threshold)
        abs_rect = offset_in_parent + scale_rect(node.roi, base)
    else:  # container / region
        if node.purpose in ("click", "input"):
            raise TreeConfigError("clickable element must be role=anchor")
        abs_rect = scale_rect(node.roi, base)
    cache.put(element_id, abs_rect, ttl=cfg.cache_ttl)
    return abs_rect
```

`match_template` 细节：
- `cv2.matchTemplate(crop, anchor, cv2.TM_CCOEFF_NORMED)`；按 `grayscale` 转灰度；
- **多尺度**：`scales=[0.9, 0.95, 1.0, 1.05, 1.1]` 分别匹配取最优（应对 DPI/窗口缩放导致锚点图尺寸轻微漂移）；
- 大区域先按 `max_side_px` 降采样再匹配，命中后坐标按比例还原（误差 < 2px，可接受）；
- `match.top_k > 1`（默认 1）时选「距父元素期望位置最近」的候选，避免命中同款按钮；
- 目标性能：单次 locate P95 < 60ms（1080p、裁剪区 ≤ 800×600）。

#### 6.2.3 缓存与失效
- 缓存 key = `element_id` + `client_rect` 哈希；TTL 默认 2s。
- **任何点击 / 滚动 / 粘贴 / 发送后立即 `cache.invalidate_all()`**（界面已变，旧坐标不可信）。
- 窗口位置或大小变化（`client_rect` 哈希变）→ 全部失效。

#### 6.2.4 失败语义（硬性）
- `ElementNotVisible` → 立即中止本 tick，随机等待 `retry_wait` 后重试 `locate_retries` 次；仍失败 → 截图留证 + 软错误（跳过本会话），计一次连续失败；**绝不复用上一次坐标、绝不用比例坐标兜底点击**。
- 弹窗遮挡：`popup_close` 在 `auto_dismiss: false`（默认）时只报告「疑似被弹窗遮挡」并暂停等待人工处理；自动关闭需显式开启且仅允许白名单元素。
- 会话切换：`locate("search_box")` → 点击 → 粘贴会话名 → 回车 → 等待 `title_verify_wait`（默认 1.5s）→ 用后续 `capture()` 的首条发送者校验（§6.3.1）；失败 → `SessionSwitchFailed`，本 tick 放弃该会话（不发送）。

#### 6.2.5 元素清单（V1.0 必须校准）

| element_id | role | purpose | required | 说明 |
|---|---|---|---|---|
| `main_window` | container | — | 是 | 根，矩形来自 pywinauto 客户端区 |
| `message_area` | region | drag | 是 | 框选拖拽区域（只给坐标，不读内容） |
| `search_box` | anchor | click | 是 | 切会话入口（用搜索，不做列表项图像匹配） |
| `input_box` | anchor | input | 是 | 点击后粘贴 |
| `send_button` | anchor | click | 否 | 仅 Enter 失效的版本启用 |
| `popup_close` | anchor | guard | 否 | 遮挡检测，默认不自动点 |
| `moments_entry` | anchor | plugin | 否 | 仅插件 `moments` 启用时需要 |

### 6.3 实时抓取（框选复制，唯一消息来源）

```python
def capture(chat, tree, cfg) -> str:
    activate_main_window()
    ensure_chat(chat, tree)  # locate(search_box) → 粘贴名字 → 回车 → §6.3.1 校验
    area = locate("message_area")  # 假树只回答"从哪里拖"
    p0, p1 = drag_points(area, cfg.drag.from_, cfg.drag.to)
    pyperclip.copy("<<SENTINEL>>")  # 哨兵：区分"复制失败"与"复制到空内容"
    mouseMove(p0, jitter=True)
    mouseDown()
    for i in (1.0).cfg.drag.steps:  # 分段拖拽，模拟人手
        mouseMove(lerp(p0, p1, i / cfg.drag.steps) + small_jitter)
    mouseUp()
    wait(cfg.drag.copy_wait)
    hotkey("ctrl", "c")
    wait(cfg.copy_wait)
    text = pyperclip.paste()
    cache.invalidate_all()  # 拖拽后选区/界面状态已变
    if text == "<<SENTINEL>>":
        raise CopyFailed  # 未选中 → 最常见的失败
    return text
```

要点：
- 拖选方向固定（右上→左下）；微信按选择顺序输出文本，方向固定才保证解析顺序稳定。
- `message_area` 与输入框留 1%~2% 空隙；拖拽起止点是**相对 `message_area` 的比例**，不写死像素。
- 剪贴板哨兵 + 复制后恢复原剪贴板（`restore_clipboard: true`）避免干扰主人。
- 失败重试：同一次抓取最多 2 次；每次重试先重新 `locate("message_area")`（绝不复用坐标）。
- **消息内容只从这里出来**：`parser` 的唯一入参是 `capture()` 返回的字符串。

#### 6.3.1 会话校验（不读标题、不做 OCR）

`capture()` 解析后，用「首条发送者名」与期望会话名做规范化比对（私聊）；群聊用「最近消息中是否出现期望成员」或「抓到的消息 hash 与库中该会话尾部至少 1 条匹配」校验。校验失败 → `SessionSwitchFailed`，放弃本 tick，不发送。
- 复用剪贴板（允许路径）完成校验，避免对会话标题区域做 OCR（禁止路径）。

### 6.4 解析（`parser.py`）

微信多选复制后的剪贴板文本形态不稳定，必须多策略。典型形态：

```
张三 2024-05-01 12:00:00
你好
李四 2024-05-01 12:01:23
在吗？
```
或单条：
```
张三：明天见
```
或群聊头部带「以上是打招呼的内容」/系统行。

策略链（依次尝试，命中即返回；每次解析都记录 `parser_strategy` 到 `raw_meta`）：

1. **S1 时间戳头行**：`^(?P<name>[^\n]{1,40}?)\s+(?P<ts>\d{4}[-/]\d{1,2}[-/]\d{1,2}\s+\d{1,2}:\d{2}(:\d{2})?)$`；
2. **S2 冒号行**：`^(?P<name>[^:：\n]{1,32})[:：]\s?(?P<content>.*)$`（后续非头行并入 content，直到下一头行）；
3. **S3 多段空行分隔**：以空行分块，块内首行若匹配 S1/S2 头，则按块解析；
4. **S4 整体降级**：无法拆分 → 视为「一段不可信文本」，生成伪消息 `sender=None, content=整块`，**只入库不回复**，并 WARN（避免误回）。

通用清洗：去零宽字符、去 `\r`、连续空行压成 1、去掉右下角「查看更多消息」等系统尾巴、过滤系统类消息（`"撤回了一条消息"`、`"以上是打招呼"`、`"[图片]"`、小额红包提示等，规则表可配 `parser/system_patterns.yaml`）。

输出结构：

```python
@dataclass
class CapturedMsg:
    sender: str | None  # 无昵称 = None（关键！用于多端识别）
    ts: str | None
    content: str
    raw_lines: list[str]
```

`ChatCaptured = list[CapturedMsg]`（屏幕顺序，旧→新）。

### 6.5 增量对齐与去重（`dedup.py`，最关键算法）

#### 6.5.1 规范化与哈希

```python
def normalize(s: str) -> str:
    s = unicodedata.normalize("NFKC", s)  # 全角→半角
    s = re.sub(r"[\u200b-\u200f\ufeff]", "", s)
    s = re.sub(r"\s+", " ", s).strip()
    return s.lower()


def h(s: str) -> str:
    return hashlib.sha1(normalize(s).encode()).hexdigest()[:16]
```

#### 6.5.2 找锚点：窗口尾部对齐

```python
def find_anchor(chat_id, screen: list[CapturedMsg], k=200) -> int | None:
    """返回 screen 中最后一条"已入库消息"的下标；屏幕比库新时就是锚点位置。"""
    db_hashes = load_recent_hashes(chat_id, k)  # 旧→新
    scr = [h(m.content) for m in screen]
    if not db_hashes or not scr:
        return None
    # 从库中最新一条往前，逐条在屏幕上"最大合法位置"匹配：
    # 要求匹配位置单调不增（旧消息在屏幕上方），连续匹配成功 >= 2 条才接受
    i, matched, best = len(db_hashes) - 1, 0, None
    pos = len(scr) - 1
    while i >= 0 and matched < 20:
        j = rfind(scr, db_hashes[i], end=pos)  # 从 pos 往前找
        if j is None:
            if matched >= 2:
                break  # 允许中间隔断（窗口边界截断）
            i -= 1
            continue
        pos = j
        i -= 1
        matched += 1
        best = j
    return best if matched >= 1 else None
```

对齐约束（写死在单测里）：
- 锚点匹配必须**单调**（旧消息在屏幕上更靠上），否则视为匹配到重复文本，回退。
- 命中 `matched >= 2` 为高置信；`matched == 1` 为低置信（仅当库内最近一条恰好是上轮自己发的，接受）。
- 找不到锚点 → 进入 `recovery`：向上滚屏 `lookback_screens` 屏重抓，二次对齐；仍失败则按 `low_confidence_policy` 处理（默认 `ignore`：整屏只入库不回，避免误回旧消息——**宁可漏回，不可错回**）。

```python
update chats.last_msg_hash = h(text)
```

下一轮抓屏时，自己发的那条已在新 `db_hashes` 里，因此它就是锚点，天然被去重。**不需要额外比对规则**——这是 README「状态回写」的正确实现方式。补充保险：

- 若抓屏底部消息 `h(content)` 等于「本进程最近一次发送内容」且库中尚不存在（回写失败），补回写而不回复。
- 发送后 15 秒内的抓屏结果若同时命中「自己刚发内容」与「对方新消息」，以自己发的为锚点继续向后取增量。

#### 6.5.4 多端并发识别（主人手机发送）

对 `new_msgs` 逐条判定：

| 会话类型 | 有昵称前缀 | 在库中 | 判定 |
|---|---|---|---|
| 私聊 | 无 | 否 | **self（主人手机端发送）** → 入库 `direction=self`，**不回复** |
| 私聊 | 有（= 对方昵称） | 否 | in → 入队回复 |
| 群聊 | 无 | 否 | self/system → 入库，不回复 |
| 群聊 | 有（成员名） | 否 | in → 入队回复（可配 `@我` 才回） |
| 任意 | 任意 | 是 | 重复 → 忽略（并 `dedup_count += 1`） |

> 歧义处理：私聊里对方若恰好没昵称前缀（某些版本复制单条时只给 `内容`），会把对方消息误判成 self → 漏回。缓解手段：① 校准期用 `/probe` 抓 3 条真实样例确认格式；② 配置 `private.no_prefix_policy: self | in | confirm`，默认 `self`（符合 README 设计），运行期可用 `/set` 动态改；③ 漏回由「主人手机上发消息后代理不回」这一可观测现象触发人工调整。

### 6.6 滚屏兜底（可选，M6 里程碑）

当 `screen` 条数 < `min_messages`（被遮罩或会话刚切），按序尝试：`locate("message_area")` 取中心 → `mouse_wheel(-3)`（向上滚）→ 重新 `locate` 后重抓；最多 `lookback_screens` 次。滚动引入焦点抢占与坐标漂移风险，故仅在 `recovery` 路径启用，且每次滚动后重新校验会话（§6.3.1）并失效定位缓存。

## 7. 调度核心：状态机与队列

### 7.1 主循环状态机

```
                  ┌──────────────── 每 tick ────────────────┐
                  ▼                                          │
 IDLE ──enabled──► CAPTURE ──有增量──► DEDUP ──有他人新消息──► ENQUEUE
  ▲                 │ 无增量/失败            │ 全为self/重复      │
  │                 └───────────────────────┴──────────────────┘
  │                                                             ▼
  │                                                   SCHEDULER 取任务
  │                                                             ▼
  │                                          BUILD_CONTEXT → THINK(LLM) → HUMANIZE
  │                                                             ▼
  │                                                     SEND（持 rpa_lock）
  │                                                             ▼
  │                                                VERIFY ──失败──► RETRY(≤2)
  │                                                             ▼
  └──────────────────────────── WRITEBACK ◄──────────────────────┘

 任意状态 ──急停/连续失败──► PAUSED ──/resume──► IDLE
```

状态与不变量：
- `PAUSED` 时不执行任何鼠标键盘动作（采集也停，避免抢占），但仍可 `/memory` 查询。
- 每个会话独立循环 `cursor`（`last_processed_msg_id`），持久化在 `chats`/`extract_cursor`，保证崩溃重启后可续。
- **同一会话串行**：一个会话在队列里最多沉淀 1 个待处理任务（同一发件人连发多条时合并为一次回复输入，见 §8.3）。
- **跨会话轮转**：`scheduler` 用加权轮转（可配 `chat_priority`），避免一个大群饿死私聊。

### 7.2 队列结构

```python
@dataclass(order=True)
class Task:
    priority: int  # 0=控制台接管, 1=@我, 2=普通
    seq: int  # 单调递增，保证 FIFO
    chat_id: int = field(compare=False)
    batch: list[CapturedMsg] = field(compare=False)  # 已合并的待回复消息
```

- 去重 key：`(chat_id, first_msg_hash)`，入队前查重。
- `drain_interruptible()`：队列阻塞等待用 `Event`，`/say` 与急停可立即打断。
- 优先级说明：待回复消息会**合并成一批**再推理（连发 3 条 → 一次上下文），避免刷屏式逐条回复（更像人）。

### 7.3 限流与静默

`TokenBucket`（会话级 + 全局）+ 静默时段判断（跨零点区间要单独处理，单测覆盖 `23:00-02:00`）。超限任务**丢弃并入库**（不回复），记 `audit_log.result='skipped'`，`/status` 可见「因限流跳过 N 条」。

## 8. 拟人化延迟与输入节奏

### 8.1 原则
- 延迟只在**真实物理动作前**生效；纯计算不延迟。
- 所有延迟支持 `interrupt_event`，急停/接管立即返回。
- `dry_run` 模式延迟照常（用于验证节奏），但不执行动作。

### 8.2 延迟模型（`delays.py`）

```python
def asap(cfg, event):
    return rand_range(*cfg.perception_delay)


def think(reply: str, cfg) -> float:
    base = rand_range(*cfg.think_delay)  # 1.5~5s
    typing = len(reply) * rand_range(*cfg.typing_ms_per_char) / 1000
    if len(reply) > 60:
        base += rand_range(*cfg.long_reply_extra)
    return min(base + typing, 15.0)  # 上限防呆


def pre_send(reply, cfg):
    return rand_range(*cfg.pre_send_delay)
```

分布：`random.uniform` 之外加 **10% 概率的"走神"**（额外 2~6s 且不回话间隔更自然），由 `humanize.occasional_pause_prob` 控制。所有随机源注入 `random.Random(seed)` 便于测试复现。

### 8.3 输入节奏
中文一律剪贴板粘贴（一次性 `Ctrl+V`），不做逐字 `typewrite`；「打字感」通过**粘贴前的等待**体现（`think_delay + typing`），这与人类行为等价且零 IME 风险。若将来要逐字效果，只能 `pyautogui.write` 英文/数字，V1 不做。

## 9. 推理层

### 9.1 上下文组装（token 预算裁剪）

```
[system] persona.md（热加载，含安全边界与"不要暴露自己是机器人"约束）
[system] 长期记忆摘要：按 importance/recency 召回 memory_top_k 条，每条 ≤ 40 字
[system] 会话摘要（若有 conversation_summary，≤ 300 字）
[user/assistant] 最近 history_turns 轮流水（从新到旧装入，超预算即停，**保留最后一轮必须完整**）
[user] 当前待回复的一批消息（含群聊成员名与时间，用编号列出）
```

预算控制：`count_tokens` 用 `tiktoken`（可选依赖）或字符数近似（中文 1 字 ≈ 0.6 token）；超 `max_prompt_tokens` 时按「会话摘要 → 更早历史 → 低 importance 记忆」顺序裁剪。

### 9.2 Prompt 模板（`assets/prompts/system.md` 片段示例）

```markdown
你正在用微信与「{{chat_name}}」聊天。你是一位真实的人，名叫{{persona_name}}。
要求：
1. 只输出要发送的消息正文，不要任何解释、引号、前后缀。
2. 长度控制在 1~3 句，口语化，符合微信聊天习惯（少用书面语、不用 Markdown）。
3. 不要自称 AI，不提及系统、模型、记忆库。
4. 群聊时若需要称呼某人，使用「@昵称 」，一次最多 @ 一人。
5. 不编造未在记忆中出现的具体事实（地址、账号、金额、日期）。
6. 对方情绪激动或涉及金钱/隐私/法律时，简短回应并留白（后续转人工）。
{{safety_rules}}
```

### 9.3 后处理（`postprocess.py`，发送前必过）

依次：去代码块/引号 → 去「微信小助手式」客套前缀 → 压缩换行（微信内多行可用，但限制 ≤ 3 行）→ 长度截断到 `max_reply_chars`（在句号处截）→ 敏感词命中 → `block_links` 命中 → 空串则视为失败不发送。**任何后处理都不允许"补全"内容**，只做删减。

### 9.4 失败策略
- `llm.py`：超时 25s、指数退避 3 次（1/2/4s），仍失败 → 按 `fail_policy`：`hold`（进入 `NEED_HUMAN`，控制台提示，`/say` 可接管）或 `skip`（丢弃，记审计）。
- 输出不合规（空/超长/含敏感）→ 直接 `hold`，不重试模型（避免死循环烧钱）。
- 记录 token 用量到 `audit_log.payload`，`/status` 显示今日消耗。

## 10. 执行层：发送与三重校验

### 10.1 发送流程

```python
with rpa_lock:  # 独占
    activate_main_window()
    ensure_chat(chat)  # 1. 标题校验
    wait(interruptible(pre_send))
    click_center(locate("input_box"))  # 2. 假 UIA 树定位输入框（失败即中止，不猜坐标）
    pyperclip.copy(text)  # 3. 写剪贴板
    hotkey("ctrl", "v")
    wait(0.15)
    # 4. 内容校验：全选复制回来比对（见 10.2）
    hotkey("ctrl", "a")
    hotkey("ctrl", "c")
    got = pyperclip.paste()
    if normalize(got) != normalize(text):
        clear_input()
        raise VerifyFailed("content_mismatch")
    hotkey("left")  # 取消全选，光标落回末尾，避免选中态被回车覆盖
    if cfg.dry_run:
        clear_input()
        return DRY_OK
    hotkey("enter")  # 5. 发送
    writeback(chat, text)  # 6. 状态回写（先写库再校验屏幕）
```

### 10.2 三重校验

| 校验 | 手段 | 失败处理 |
|---|---|---|
| 窗口/会话正确 | 标题文本与期望会话名比对（模糊匹配去空格/emoji） | 重切会话一次；再失败 → 中止，不发送 |
| 输入框已聚焦 | `Ctrl+A → Ctrl+C` 得到的内容 == 刚粘贴文本；空文本时检测 `Ctrl+A` 后是否出现选区（截图 ROI 像素差） | 重新点击输入框（位置 +2px 抖动）；2 次后中止 |
| 内容一致 | 规范化后完全相等（标点/空白容忍差异，正文不容忍） | 清空重来 1 次；再失败 → 中止并告警 |

发送后确认（采样，默认 30% 概率或首条必查）：重新 `capture()`，检查末尾消息 hash == 待发文本；不一致 → 记 `verify_failed` 并告警（**不回滚、不重发**，防止双发）。

### 10.3 失败恢复
- 每次失败立即截图 `data/screenshots/fail_<ts>_<reason>.png` + 记录 `audit_log`。
- 连续 `max_consecutive_failures` 次 → 自动 `PAUSED`，控制台醒目告警（含截图路径与最近 5 条审计）。
- 坐标漂移/界面突变防护：动作前 `validate_profile()`（分辨率/DPI/`client_rect` 一致）；发送前若 `locate()` 连续 `ElementNotVisible`，或 `capture()` 内容与期望会话历史完全不匹配 → 判定窗口被切换/界面已变，`ensure_chat` 重建后重试；仍失败 → 中止并自动 `PAUSED`。

### 11.2 自然语言指令路由（`nlu.py`）

- `control.nlu_enabled=true` 时，输入不以 `/` 开头 → 先**本地规则**匹配（含关键词：暂停、恢复、发消息给X、改人设、记得、忘掉、总结、状态…），命中即执行；
- 未命中 → 调 LLM（`assets/prompts/intent.md`），要求输出严格 JSON：`{"intent": "...", "args": {...}, "confidence": 0.0~1.0}`；`confidence < 0.7` 或非法 JSON → 回显「没听懂，按 `/say` 处理？」并**不执行**；
- 高危 intent（`say`、`config.set`、`forget`）强制二次确认 `y/N`；
- 离线（LLM 不可用）时自动降级为纯规则模式并提示。

### 11.3 线程与交互安全
- 控制台读 `stdin` 在独立线程，结果回显走 `rich`（无则 `print`）；**RPA 动作与读 stdin 互不阻塞**。
- 全局热键（`pynput`，非注入）：`Ctrl+Alt+Q` 立即急停（暂停 + 释放锁 + 可选退出），`Ctrl+Alt+P` 暂停/恢复。热键只在 RPA 持锁间隙被消费（回调只置 `Event`，不做动作）。
- 主人物理操作干扰检测（可选 M5）：动作前 `pyautogui.position()` 与预期路径偏差过大 / 动作后窗口失焦 → 立即放弃本 tick（避免"跟主人抢鼠标"）。

## 12. 扩展接口层

```python
# plugins/base.py
class PluginBase(Protocol):
    name: str
    version: str
    commands: dict[str, Callable]        # 控制台子指令，如 "#发圈 <文本>"
    def on_start(self, ctx: AgentContext) -> None: ...
    def on_message(self, ctx, chat, msg) -> bool: ...   # 返回 True 表示已消费（不再走 AI）
    def on_tick(self, ctx) -> None: ...

@dataclass
class AgentContext:                  # 插件能拿到的最小能力集（不给裸 pyautogui）
    send_text(chat: Chat, text: str, *, trigger="plugin") -> bool
    capture(chat: Chat) -> list[CapturedMsg]
    db: MemoryHub
    log: Logger
    config: Config
```

- `moments.py`（示例，默认 `enabled: false`）：`#发圈 <文本> [--private]` → 点「朋友圈」→ 点相机 → 粘贴 → 发布；所需界面元素作为 `purpose=plugin` 节点加入假 UIA 树 profile（`moments_entry` 等），失败不影响主流程。表结构 `moments_log(id, content, visibility, result, created_at)` 由插件自建。
- Task Scheduler：`tasks` 表 + 主循环每 tick 扫 `run_at <= now AND state='pending'`，交给对应插件；失败重试上限 3 次。
- 插件强约束：**不得在插件内 `import pyautogui` 直接操作**，必须走 `ctx.send_text`，以保证审计与锁的完整性。

## 13. 安全、合规与隐私

1. **零注入**：全程只用公开 Win32/UIA 消息与物理外设模拟；明确不读微信内存、不碰进程、不装证书、不模拟网络协议。
2. **频率合规**：默认限流远低于人工上限（私聊 ≤6 条/分钟），静默时段不复。
3. **隐私**：`data/` 全量本地；日志与截图默认脱敏（手机号、身份证正则打码）并 7 天轮转删除；`/summary` 等操作不把内容外发到除 LLM API 之外的任何地方（需在文档与启动 banner 中明示）。
4. **人类在环**：默认 `dry_run` 首跑；风险内容（金额、地址、身份、法律）一律不自动回复，转 `/say`。
5. **可停止**：急停热键 + `/quit` 优雅退出（落盘 → 释放剪贴板原内容 → 恢复系统状态）。
6. **免责**：README 已声明独占鼠标与分辨率依赖；代码里 `doctor.py` 首跑强制检查并打印提示。

## 14. 异常处理与可观测性

### 14.1 异常分类（`core/errors.py`）

| 异常 | 场景 | 处理 |
|---|---|---|
| `WindowNotFound` | 微信未启动/被关闭 | 指数退避重试 30s，超时暂停 + 告警 |
| `SessionSwitchFailed` | 会话切换失败 | 重试 1 次，失败跳过该会话本 tick |
| `CopyFailed` | 剪贴板未被覆盖 | 重新点击后重抓，2 次后跳过 |
| `ElementNotVisible` | 假 UIA 树锚点图匹配低于阈值（弹窗遮挡/界面突变） | 立即中止本 tick，抖动重试 `locate_retries` 次；仍失败 → 截图 + 软错误跳过，绝不猜坐标 |
| `ProfileMismatch` | 分辨率/DPI/窗口矩形与 profile 不符 | 拒绝动作、`PAUSED` 并提示 `/calibrate` |
| `SessionSwitchFailed` | 切会话后校验不通过 | 放弃本 tick，不发送，重试 1 次 |
| `CopyFailed` | 剪贴板未被覆盖（未选中） | 重定位后重抓 2 次，失败跳过 |
| `AnchorLost` | 去重锚点找不到（消息窗口截断/滚屏） | 滚屏恢复；仍失败按策略入库不回 |
| `LLMError` | 网络/额度/超时 | 退避重试 3 次 → `hold` |
| `VerifyFailed` | 标题/焦点/内容校验失败 | 清空重来 1 次 → 中止，计入连续失败 |
| `Interrupted` | 急停/接管 | 立即返回，不落任何半成品消息 |

### 14.2 日志与审计

- `data/logs/agent.log`：`RotatingFileHandler`（10MB × 5），格式 `ts level [trace_id] [chat] msg`；`trace_id` 串联「采集→推理→发送」全链路。
- `data/logs/audit.jsonl`：与 `audit_log` 表同源，便于外部 grep。
- 阶段耗时打点：`capture_ms / llm_ms / send_ms`，`/status` 展示 P50/P95（最近 100 次，内存统计即可）。
- 健康自检 `doctor.py`：Python 版本、依赖、DPI 缩放、多屏坐标（含负坐标）、热键占用、API 连通性、写权限、库可打开。

### 14.3 崩溃恢复
启动顺序：加载配置 → 打开双库（跑迁移）→ 恢复 `PAUSED`/`IDLE` 状态（**上次非正常退出则默认 PAUSED**）→ 恢复队列（从库里重建未回复的 `direction=in` 且 `id > chats.last_processed_msg_id` 的消息）→ 启动线程。恢复时对「最后一条 out 消息」做一次抓屏确认是否真发出去了，避免双发。

## 17. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 微信版本 UI 变化（3.9 vs 4.x） | 复制格式/页面布局全变 | 解析器多策略 + 假树 profile 按分辨率/DPI 分文件 + `parser/system_patterns.yaml` 可配置；升级只需重校准+补样例 |
| 锚点图失效（深色模式/主题/字体渲染/版本皮肤） | 定位全失败，机器人停摆 | 每元素支持多张备选锚点图（`anchor_images: []` 按序尝试）；校准向导支持浅色/深色各录一套；启动 `validate-tree` 自检，失效即提示重校 |
| 模板误命中（同款按钮/相似区域） | 点错位置（最严重） | 父区域裁剪 + 多候选取最近 + 高阈值（0.88~0.92）+ 命中后二次校验（焦点回读/复验），失败即中止 |
| 匹配耗时过高 | 单轮延迟变长 | 祖先裁剪 + 降采样 + 缓存 TTL；`locate` P95 < 60ms 作为性能门禁 |
| 复制格式不稳定/无昵称前缀 | 多端误判（漏回/错回） | 默认「宁可漏回不错回」；`private.no_prefix_policy` 可切；`/probe` 快速定位 |
| 鼠标拖选选中失败/选中色块 | 采集异常 | 哨兵剪贴板 + 重试 + 只从文本区中段拖选；失败跳过不猜 |
| 坐标漂移（DPI/窗口移动/多屏） | 发到错误会话（最严重） | 假树 `ProfileMismatch` 校验 + 会话/焦点/内容三重校验 + 窗口矩形变化即告警暂停 |
| 输入法/焦点问题 | 内容错/发空 | 仅粘贴；`Ctrl+A` 回读比对；`left` 取消全选；失败清空重来 |
| LLM 不听话（输出解释/Markdown） | 消息难看 | 强约束 prompt + 后处理删减 + 空则 hold |
| 拟人延迟过长导致消息堆积 | 回复滞后 | 队列合并 + 上限 15s + 积压超阈值直接回「在忙，稍后」策略（可配） |
| 抢占鼠标影响主人 | 体验差/误操作 | 副屏方案 + 急停热键 + 静默时段 + 干跑模式 |
| 隐私/账号风险 | 封号 | 零注入、低频率、不群发、不营销、不自动加好友 |

## 19. 附：一个 tick 的完整时序（参考实现顺序）

```
tick(now):
  if paused or in_quiet_hours(now) or over_budget(now): return
  tree.ensure_profile()                               # 分辨率/DPI/client_rect 与 profile 一致，否则暂停
  for chat in scheduler.next_chats(limit=2):          # 每 tick 最多处理 2 个会话，均摊开销
      if not chat.enabled or not chat.auto_reply: continue
      try:
          raw   = capture(chat, tree)                 # 1. 感知：locate(message_area) + 框选 + Ctrl+C
          msgs  = parse(raw)                          # 2. 解析（唯一消息来源）
          if len(msgs) < cfg.min_messages: recover_scroll(chat); continue
          new   = dedup.extract_new(chat, msgs)       # 3. 增量对齐
          persist(new)                                # 4. 入库（self/重复都在此落库）
          replyable = [m for m in new if m.direction == "in"]
          if not replyable: continue
          task  = queue.enqueue(chat, replyable)      # 5. 入队（合并同会话）
      except (ElementNotVisible, ProfileMismatch, CopyFailed, SessionSwitchFailed) as e:
          handle_soft_error(chat, e); continue        # 软错误：跳过本会话，计数，不猜坐标

  task = queue.try_pop()                              # 6. 取任务（跨会话轮转）
  if task:
      ctx = build_context(task)                       # 7. 记忆 + 历史 + 人设
      reply = llm.chat(ctx)                           # 8. 推理
      reply = postprocess(reply)                      # 9. 清洗
      wait(humanize.think(reply))                     # 10. 拟人停顿
      executor.send(task.chat, reply)                 # 11. locate(input_box) + 粘贴 + 三重校验 + 回车 + 回写
      ratelimit.consume(task.chat)
  scheduler.sleep_until_next_tick()                   # interruptible
```
