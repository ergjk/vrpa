# ADR-0001：框架底座与应用分层（双顶层包）

- 状态：**Accepted**
- 日期：2026-11-06
- 决策人：主控官
- 关联：ADR-0002（配置 schema v2）、ADR-0003（接口稳定与适配器契约）

## 背景

项目原定位是「V1.0 微信智能体」，M0 基建（配置/日志/异常/接口）按应用内模块实现，位于 `wechat_agent.core`。
主控官决策：M0 基建同时作为**可复用多平台 RPA 框架底座**，使未来开发者能无缝替换感知层、复用于 QQ/钉钉等场景。
现有底座存在平台耦合：配置顶层 `wechat:` 段、异常基类与应用名强绑定、logger 名 `wechat_agent`、
`capture(chat)`/`ensure_chat()` 会话语义、缺失适配器契约与合规测试套件；同时缺少 pyproject/ruff/mypy/覆盖率门禁。

## 决策

1. 仓库采用**双顶层包**：`vrpa`（平台无关框架底座，仅标准库依赖）+ `wechat_agent`（微信应用与适配器）；
2. 依赖单向：`wechat_agent -> vrpa -> stdlib`；`vrpa` 禁止 import 应用层；
3. 平台差异由 `PlatformAdapter` 协议 + `AdapterRegistry` + 平台配置插件表达；
4. 「可替换感知层」以**适配器合规测试套件**（`vrpa.testing.contracts`）为强制判定标准；
5. 迁移采用**兼容 shim + 弃用告警**，旧路径/旧类名/旧环境变量保留一个版本；
6. 质量门禁（ruff / ruff format / mypy strict / pytest / coverage ≥ 85%）在 M0-F-01 即生效。

6. （2026-11-06 主控官决定）框架包最终定名 **`vrpa`（Vision RPA）**；旧包名兼容 shim 已按指令彻底移除；环境变量统一 `VRPA_*`，应用层保留 `WECHAT_AGENT_*` 回退。

## 备选方案与被否原因

| 方案 | 否决原因 |
|---|---|
| 单包内 `framework/` + `adapters/` 子目录 | 第三方复用需引入整个应用包；发布单元与依赖边界不清 |
| 保持现状仅文档声明分层 | 无强制力，"可替换"退化为口号；平台耦合会随 M1/M2 继续扩散 |
| 先完成 M0-07~09 再统一重构 | doctor/控制台/红线工具要写两遍，且新代码会继续长在旧分层上 |

## 后果

**正面**：框架可独立发布与测试；新增平台只需实现适配器并通过 contracts；应用层职责清晰；质量门禁可量化。

**代价**：一次性重构成本（约 2~3 人日）；过渡期存在两套路径（shim）；需要维护 ADR/指南/CHANGELOG。

**风险与缓解**：
- shim 遗漏 → 旧测试全绿作为回归门禁；
- 概念膨胀（ports vs 应用接口）→ 框架 ports 只保留最小能力集，应用可扩展；
- 适配器契约过度约束 → contracts 只约束行为语义，不约束实现细节（元素定位方式、解析策略可自由实现）。

## 迁移计划

见 `docs/architecture.md` §7（M0-F-01 ~ M0-F-06），每步保持 `pytest tests` 全绿。
