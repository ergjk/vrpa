# 聊天记录获取：V1.0 当前第一瓶颈

> 状态：问题说明 + 社区征集。  
> 这不是单个 bug，而是采集架构的边界问题。

## 1. 为什么是瓶颈

V1.0 已经能完成：

```text
激活微信 → 定位消息区 → 框选 → Ctrl+C → 解析 → 去重 → 入库
```

但它只能稳定拿到：

- 当前窗口；
- 当前选区覆盖的文本；
- 微信已经加载到本地的部分。

它不能保证：

- 历史全量；
- 群聊完整归档；
- 图片/语音/文件/引用；
- 任意 DPI/窗口位置；
- 采集覆盖率可证明。

因此“采集一次”不是瓶颈，“如何证明拿全、拿对、可持续”才是瓶颈。

## 2. 已尝试/已评估的路径

| 路径 | 结论 |
|---|---|
| 鼠标拖拽 + Ctrl+C | 当前主路径，可用但不完整 |
| Ctrl+A 全选 + Ctrl+C | 实测微信消息区无效，剪贴板不变 |
| 多选 + 复制/合并转发 | 可精确补录，但大批量慢 |
| 人工复制 + 剪贴板监听 | 最稳，但需要人工 |
| 官方备份/迁移 | 完整性最好，但恢复后才能导出 |
| Windows UIA 读取 | 未验证，微信 4.x 可能不可用 |
| Alt+A 截图 + 本地离线 OCR | 仅作为受限兜底；禁止云 OCR/第三方 API |
| 本地数据库解密 | 不纳入方案 |
| 协议逆向/Hook | 不纳入方案 |
| QQ 官方 Bot API | QQ 场景优先，但不是个人账号历史 |

## 3. 具体未解问题

### A. 历史回填

- 如何可靠向上滚动并判断“到顶”？
- 如何做块间重叠与去重？
- 如何记录游标，重进后继续？
- 如何证明没有漏块？

### B. 群聊身份

- 群昵称/QQ 昵称/备注名不一致；
- 同一人改名；
- 自己/他人/机器人身份判定；
- @、引用、回复关系。

### C. 非文本消息

- 图片、语音、文件、表情、卡片；
- 是否只入库占位，不回复；
- 是否需要 OCR（仅限本地、显式同意）。

### D. 覆盖率

- 消息数量、时间范围、首尾哈希；
- 块间断档检测；
- 无法判断时必须标记 `INCONCLUSIVE`，不能写 PASS。

## 4. 征集什么

欢迎提交**可复现的获取方法**，不要求代码：

1. 平台与版本（微信 4.x / QQ 9.x / NT / 手机 / 其他）；
2. 操作系统、分辨率、DPI；
3. 操作步骤；
4. 能拿到什么、拿不到什么；
5. 是否可自动化；
6. 隐私与平台规则风险；
7. 样例格式（请脱敏，勿上传真实聊天）；
8. 失败案例同样欢迎。

## 5. 不征集

- 破解账号/数据库密钥；
- 绕过登录、权限、风控；
- 上传他人聊天记录；
- 云 OCR/第三方 OCR API；
- 大规模群发、加好友、营销自动化。

> V1.0 的下一阶段，不应先加回复功能，而应先解决“聊天记录获取”的可证明性。
